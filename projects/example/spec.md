# 회의실 예약 (예시)

> [!NOTE]
> **이 프로젝트는 실제로 만들 서비스가 아니에요.** 기획 스킬과 파이프라인(`/pipeline:kickoff` → `plan` → …)이 제대로 동작하는지 확인하려고 만든 예시입니다. 실제 개발 대상으로 보지 말고, 스킬을 처음 써 보는 사람이 기획서가 어떻게 나오는지 참고하는 용도로 쓰세요.

> 정보운영팀 팀원이 폰으로 회의실이 비었는지 보고 미리 예약하는 서비스

## 배경

지금은 회의실 예약을 따로 받지 않는다. 먼저 와서 쓰는 사람이 쓰는, 거의 선착순 방식이다. 그래서 회의실 앞까지 가 봐야 비어 있는지 알 수 있고, 다음 회의를 위해 회의실을 미리 잡아둘 방법이 없다.

## 사용자

| 역할       | 누구인지              | 기기          | 이 서비스에서 하는 일  |
| ---------- | --------------------- | ------------- | ---------------------- |
| 팀원 | 정보운영팀 팀원 (출근부·업무일지와 같은 로그인) | 모바일 | 회의실이 비었는지 보고, 날짜·시간을 골라 미리 예약 |
| 관리자 | 정보운영팀 관리자 | 모바일 | 전체 예약을 보고, 필요하면 예약을 취소하거나 규칙을 정함 |

## 핵심 시나리오

사용자가 실제로 하는 일을 순서대로 적습니다. 화면 이름은 아래 화면 목록의 ID를 씁니다.

### S1. 회의실 예약하기 (팀원)

1. 앱을 열면 S-01(오늘 하루 시간표)이 보인다. 30분 칸마다 비었는지, 누가 무슨 회의로 잡았는지 보인다
2. 옆으로 넘겨 원하는 날짜로 간다
3. 빈 칸에서 시작 칸과 끝 칸을 누른다 → S-02(예약하기)로 이동
4. 회의 이름을 적고 '예약하기'를 누른다
5. 예약이 바로 확정되고, S-01 시간표의 그 칸에 내 이름과 회의 이름이 채워진다

### S2. 예약 취소하기 (팀원)

1. S-01에서 예약한 날짜로 넘긴다
2. 내 예약 칸을 누른다 → S-03(예약 상세)이 뜬다
3. '예약 취소'를 누르고, 확인 팝업에서 한 번 더 확인한다
4. 그 시간이 다시 빈 칸이 된다

### S3. 다른 사람 예약 취소하기 (관리자)

1. S-01(팀원과 같은 시간표)에서 해당 날짜로 넘긴다
2. 취소할 예약 칸을 누른다 → S-03(예약 상세). 관리자에게는 남의 예약에도 '예약 취소' 버튼이 보인다
3. '예약 취소'를 누르고 취소 사유를 한 줄 적은 뒤 확인한다
4. 그 시간이 빈 칸이 된다
5. 예약했던 팀원이 다음에 앱을 열면 '관리자가 취소한 예약이 있어요' 안내와 취소 사유가 보인다 (폰 알림은 없다)

### S4. 예약 못 하는 시간 막기 (관리자)

1. S-01에서 막을 날짜로 넘기고, 시작 칸과 끝 칸을 누른다 → S-02(예약하기)
2. 관리자에게는 S-02에 '예약 / 시간 막기' 선택이 보인다. '시간 막기'를 고르고 사유를 적는다 (예: 청소)
3. 그 시간에 이미 예약이 있으면 "예약 N개가 함께 취소돼요" 확인 팝업이 뜬다
4. 확인하면 그 시간이 '막힘'(사유 표시)으로 바뀌고, 겹친 예약은 취소된다. 막는 사유가 곧 취소 사유가 된다
5. 예약이 취소된 팀원은 S3처럼 다음에 앱을 열 때 안내를 본다
6. 잘못 막았으면 막힌 칸을 눌러 S-03에서 '막기 풀기'를 누른다. 빈 칸으로 돌아가지만, 막을 때 취소된 예약은 되살아나지 않는다

### S5. 운영 규칙 바꾸기 (관리자)

1. S-01 위쪽의 '운영 규칙' 버튼(관리자에게만 보임)을 누른다 → S-04(운영 규칙)
2. 예약 가능한 시간대(예: 평일 9시~18시)와 한 번에 잡을 수 있는 최대 길이(예: 2시간)를 바꾼다
3. '저장'을 누르면 그때부터 S-01 시간표 범위와 예약 길이 제한이 바뀐다. 새 규칙 밖에 이미 잡힌 예약이 있으면 "규칙 밖에 있는 예약 N개는 그대로 남아요" 안내를 보여주고, 그 예약은 그대로 둔다

| ---- | ---- | ---- | ---- | ------- | ------- |
| S-01 | 시간표 | 팀원, 관리자 | 모바일 | 하루 시간표 (30분 칸마다 비었는지, 누가 무슨 회의인지, 막힌 시간) | 날짜 넘기기, 빈 칸 골라 예약, 예약 칸 눌러 상세 보기 |
| S-02 | 예약하기 | 팀원, 관리자 | 모바일 | 고른 날짜·시간 | 회의 이름 적고 예약 / (관리자) 사유 적고 시간 막기 |

| S-04 | 운영 규칙 | 관리자 | 모바일 | 지금 규칙 | 예약 가능한 시간대, 최대 길이 바꾸기 |

## 화면 상세

### S-01. 시간표

- **보이는 것** (위에서 아래로):
  1. (관리자가 내 예약을 취소했을 때만) 안내 메시지: "관리자가 취소한 예약이 있어요 · 10/31(금) 14:00~15:00 · 사유: 학교 행사". '확인'을 누르면 사라진다
  2. 날짜와 좌우 화살표, '오늘' 버튼. (관리자에게만) '운영 규칙' 버튼
  3. 시간표: 예약 가능한 시간대를 30분 칸으로 나열. 칸마다 다음 중 하나
     - 빈 칸
     - 예약됨: 예약한 사람 이름, 회의 이름 (여러 칸에 걸친 예약은 한 덩어리로). 내 예약은 색을 달리한다
     - 막힘: 회색, 사유 표시 (예: 청소)
     - 지난 시간: 흐리게, 누를 수 없음
- **할 수 있는 것**:
  - 화살표나 좌우로 밀어 날짜 이동, '오늘'로 돌아오기
  - 빈 칸에서 시작 칸 → 끝 칸을 누르면 그 사이가 선택되고, 아래에 '이 시간 예약하기' 버튼이 뜬다 → S-02
  - 예약 칸을 누르면 S-03
  - (관리자) '운영 규칙' → S-04
- **비어 있을 때**: 그날 예약이 하나도 없으면 시간표 전체가 빈 칸으로 보이고, 위에 "아직 예약이 없어요" 한 줄
- **안 될 때**:
  - 지난 시간, 예약된 칸, 막힌 칸은 고를 수 없다
  - 고른 길이가 최대 길이를 넘으면 "한 번에 최대 2시간까지 예약할 수 있어요" 안내, 끝 칸이 선택되지 않는다
  - 예약 가능한 시간대 밖(예: 주말)은 "예약할 수 없는 날이에요"
  - 오늘부터 2주가 넘는 날짜로는 넘어가지 않는다

### S-02. 예약하기

- **보이는 것** (위에서 아래로):
  1. 날짜와 시간 (예: 10/31(금) 14:00~15:00)
  2. (관리자에게만) '예약 / 시간 막기' 탭
  3. 예약: 회의 이름 입력칸 (필수) / 시간 막기: 사유 입력칸 (필수)
  4. 하단 고정 버튼: '예약하기' 또는 '시간 막기'
- **할 수 있는 것**:
  - '예약하기' → 바로 확정, S-01로 돌아가 그 칸이 채워진다
  - (관리자) '시간 막기' → 겹치는 예약이 있으면 "예약 N개가 함께 취소돼요" 확인 팝업 → 확인하면 막힘으로 바뀌고 S-01로 돌아간다
- **비어 있을 때**: 회의 이름(또는 사유)이 비어 있으면 버튼이 눌리지 않는다
- **안 될 때**: 그 사이 다른 사람이 같은 시간을 먼저 예약했으면 "방금 다른 사람이 예약했어요" 안내 후 S-01로 돌아간다

### S-03. 예약 상세

- **보이는 것** (위에서 아래로):
  1. 회의 이름
  2. 예약한 사람
  3. 날짜와 시간
  4. (내 예약이거나 관리자일 때) '예약 취소' 버튼
- **할 수 있는 것**:
  - 팀원(내 예약): '예약 취소' → "이 예약을 취소할까요?" 확인 팝업 → 취소하고 S-01로
  - 관리자(남의 예약): '예약 취소' → 사유 입력 팝업 → 취소하고 S-01로. 예약한 팀원에게 S-01 안내 메시지가 생긴다
  - 남의 예약을 본 팀원: 보기만 하고 버튼은 없다
  - 막힌 시간을 누르면 사유와 시간이 보인다. 관리자에게는 '막기 풀기' 버튼이 보이고, 누르면 빈 칸이 된다
- **비어 있을 때**: 해당 없음
- **안 될 때**: 이미 시작했거나 지난 예약은 '예약 취소' 버튼이 보이지 않는다

### S-04. 운영 규칙

- **보이는 것** (위에서 아래로):
  1. 예약 가능한 시간대: 요일 선택 (월~일), 시작 시각, 끝 시각 (30분 단위)
  2. 한 번에 잡을 수 있는 최대 길이 (30분 단위)
  3. 하단 고정 버튼: '저장'
- **할 수 있는 것**: '저장' → 그때부터 S-01 시간표 범위와 길이 제한이 바뀐다. 새 규칙 밖에 이미 잡힌 예약이 있으면 저장 전에 "규칙 밖에 있는 예약 N개는 그대로 남아요" 확인 팝업을 보여준다. 그 예약은 시간표에 그대로 보인다
- **비어 있을 때**: 처음에는 기본값이 들어 있다
- **안 될 때**: 끝 시각이 시작 시각보다 빠르면 저장이 눌리지 않는다. 관리자가 아니면 이 화면에 들어올 수 없다

### 상태

| 대상 | 상태 | 뜻 | 다음 상태로 바뀌는 때 |
| ---- | ---- | -- | -------------------- |
| 예약 | 확정 | 예약하는 즉시 이 상태. 시간표에 보인다 | 예약한 팀원이 시작 전에 취소하면 → 취소됨. 관리자가 취소하거나 그 시간을 막으면 → 관리자 취소 |
| 예약 | 취소됨 | 예약한 팀원이 스스로 취소함. 시간표에서 사라진다 | 바뀌지 않는다 |
| 예약 | 관리자 취소 | 관리자가 취소하거나 시간을 막아 취소됨. 사유가 남는다 | 바뀌지 않는다. 팀원이 안내를 '확인'하면 안내만 사라진다 |

취소된 예약도 지우지 않고 기록으로 남긴다. 기록을 보는 화면은 이번에 만들지 않는다.

## 규칙

- 예약할 수 있는 회의실은 1개다. 회의실을 고르는 단계가 없다
- 예약은 30분 단위로 잡는다
- 예약은 이어진 빈 칸으로만 잡을 수 있다. 예약된 칸이나 막힌 칸을 사이에 두고 고를 수 없다
- 기본 운영 규칙: 평일(월~금) 9시~18시, 한 번에 최대 2시간. 관리자가 S-04에서 바꿀 수 있다
- 운영 규칙을 바꿔도 이미 잡힌 예약은 그대로 남는다. 바뀐 규칙은 새로 하는 예약에만 적용된다. 꼭 비워야 하면 관리자가 하나씩 취소한다
- 한 팀원이 잡을 수 있는 예약 개수는 제한하지 않는다. 문제가 생기면 관리자가 취소한다
- 오늘부터 2주 앞까지만 예약할 수 있다 (고정, 관리자가 바꾸는 규칙이 아니다)
- 예약 취소: 팀원은 자기 예약만, 관리자는 모든 예약을 취소할 수 있다. 시간 막기와 운영 규칙은 관리자만 한다
- 관리자는 막힌 시간을 풀 수 있다. 풀어도 막을 때 함께 취소된 예약은 되살아나지 않는다
- 관리자가 남의 예약을 취소할 때만 사유를 적는다. 자기 예약은 팀원과 똑같이 취소한다
- 예약은 누르는 즉시 확정된다. 관리자 승인 단계는 없다
- 예약은 고칠 수 없다. 시간이나 회의 이름을 바꾸려면 취소하고 다시 예약한다
- 지난 시간은 예약할 수 없다. 이미 시작했거나 끝난 예약은 취소할 수 없다 (일찍 끝나도 남은 시간을 풀지 않는다)

| 관리자가 남의 예약 취소 (사유 적기) | S-03 | 보통 | 꼭 필요 | 예약 개수 제한이 없어서, 문제가 생기면 정리할 방법이 이것뿐이다 |
| 관리자 취소 안내 메시지 | S-01 | 작음 | 있으면 좋음 (여유가 생기면 가장 먼저) | 없으면 관리자가 카톡으로 직접 알린다 |
| 시간 막기 (겹친 예약 함께 취소) | S-02 | 큼 | 있으면 좋음 | 없으면 관리자가 "청소" 같은 이름으로 예약해 둔다 |
| 운영 규칙 바꾸기 | S-04 | 보통 | 있으면 좋음 | 없으면 기본값(평일 9~18시, 최대 2시간)으로 고정하고, 바꿀 일이 생기면 개발자가 고친다 |

- 개발 인원과 기간: 개발자 1명(화면과 서버 모두), 지금부터 다음 학기 시작 전(2027년 3월)까지 약 17주. 겨울방학 동안 만들고 개강 전에 연다
- 어림: 1명이 화면과 서버를 모두 하면 '보통' 하나에 약 2주. 꼭 필요 5개는 약 13주로 기간 안에 들어가고, 있으면 좋음 1~2개를 더 넣을 여유가 있다
