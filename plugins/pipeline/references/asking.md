# 비개발자에게 묻는 법

기획 단계 스킬(`kickoff`, `plan`, `interview`, `scope`, `stories`, `red-team`)이 함께 따르는 질문 규칙이다. 상대는 개발도 기획도 전문으로 하지 않는 학생이다. 이 단계의 품질은 질문의 질에서 나온다. 답하기 쉬운 질문이 좋은 질문이다.

## 8가지 규칙

### 1. 왜 묻는지 먼저 말한다

질문만 던지지 않는다. 이 답이 **화면이나 규칙의 어디를 정하는지** 한 줄로 먼저 말한다.

> 이걸 정해야 학생 화면에 '예약 취소' 버튼을 둘지 정할 수 있어요.
> 학생이 예약을 스스로 취소할 수 있나요?

### 2. 선택지마다 고르면 어떻게 되는지 쓴다

선택지 이름만 주지 않는다. 고르면 **화면이 어떻게 달라지는지, 일이 얼마나 늘어나는지, 좋은 점과 아쉬운 점**을 쓴다. 추천이 있으면 첫 번째에 두고 `(추천)`을 붙이고, 왜 추천하는지 한 줄 쓴다.

### 3. "잘 모르겠어요"를 항상 선택지로 둔다

선택지 마지막은 언제나 "잘 모르겠어요"다. 설명에는 "Claude가 흔한 방식으로 임시로 정하고, 나중에 확인할 목록에 남겨둘게요"라고 쓴다. 이걸 고르면:

1. 추천안을 임시로 적는다
2. 기획서 `열린 질문`에 `(임시: <정한 것>) 누구에게 물어볼지`를 남긴다
3. 답을 아는 사람이 따로 있으면 `/pipeline:interview` 질문지에 넣자고 제안한다

### 4. 장면으로 묻는다

추상적인 질문은 답하기 어렵다. 실제로 서비스를 쓰는 **한 장면**을 그려서 묻는다.

| 이렇게 묻지 않는다         | 이렇게 묻는다                                                                   |
| -------------------------- | ------------------------------------------------------------------------------- |
| 관리 기능이 필요한가요?    | 월요일 아침에 관리자가 이 화면을 열면, 가장 먼저 뭘 확인하나요?                 |
| 예외 처리는 어떻게 할까요? | 학생이 예약한 날 안 오면 어떻게 되나요? 그 노트북은 다른 사람이 빌릴 수 있나요? |
| 권한은 어떻게 나눌까요?    | 근로학생도 장비를 새로 등록할 수 있나요, 아니면 관리자만 하나요?                |

팀에 이미 있는 서비스(출근부, 업무일지)와 비슷한 부분은 그걸 예로 든다. "출근부에서 근무 신청할 때처럼 ~"

### 5. 질문은 한 번에 하나, 진행 상황을 보여준다

- 한 메시지에 질문 하나만 한다. 답을 듣고 다음 질문을 정한다
- 질문 앞에 지금 위치를 쓴다: `[기획서 2/5단계 · 시나리오] 질문 3/약 6`
- 질문 수는 대략이어도 된다. 끝이 보이면 덜 지친다
- 사용자가 "그만", "나중에"라고 하면 지금까지 내용을 저장하고, 다음에 어디서 이어가면 되는지 알려준다

### 6. 들은 걸 되풀이해 확인한다

질문 3~4개마다, 그리고 단계가 끝날 때 지금까지 정한 것을 짧게 정리해 보여주고 맞는지 묻는다.

> 지금까지 정리하면:
>
> - 학생은 앱에서 미리 예약하고, 창구에서 받아요
> - 장비 종류마다 한 개씩 빌릴 수 있어요
> - 예약한 날 안 오면 그날 저녁 자동으로 취소돼요
>
> 맞나요? 틀린 곳이 있으면 알려주세요.

### 7. 처음 나오는 말은 풀어 쓴다

- 코드 용어는 쓰지 않는다: 엔드포인트, 엔티티, 스키마, CRUD, 상태 관리, API, DB 등. "화면", "버튼", "목록", "기억해 둘 정보", "서버(정보를 저장하는 컴퓨터)"로 말한다
- 서비스 안에서 쓸 낱말은 처음 나올 때 뜻을 정해 확인받는다. 비슷한 말을 섞어 쓰지 않는다
  > "예약"은 미리 찜만 해둔 것, "대여"는 장비를 실제로 가져간 것으로 나눠서 부를게요. 괜찮나요?
- 정한 낱말은 기획서 `데이터` 표의 한글 이름과 같게 쓴다

### 8. 나중에 바꾸기 어려운 결정은 표시한다

아래 같은 결정은 나중에 바꾸면 화면과 서버를 다 고쳐야 한다. 질문 앞에 `⚠️ 나중에 바꾸기 어려워요`를 붙이고, 선택지 설명을 더 자세히 쓰고, 답을 받은 뒤 한 번 더 확인한다.

- 누가 쓰나 (역할), 로그인 방식
- 하나를 세는 단위 (장비 종류별 개수만 셀지, 한 대씩 번호로 구분할지)
- 단계가 있는 것의 상태 (신청 → 승인 → 완료 등)
- 무엇을 기록으로 남길지 (지난 기록을 볼 수 있어야 하는지)

반대로 문구, 버튼 위치, 색처럼 쉽게 바꿀 수 있는 것은 길게 묻지 않고 Claude가 정한 뒤 화면 단계에서 보여준다.

## AskUserQuestion 쓰는 법

선택지가 있는 질문은 AskUserQuestion으로 묻는다. 규칙을 이렇게 옮긴다.

| 칸                      | 쓰는 것                                                       |
| ----------------------- | ------------------------------------------------------------- |
| `header`                | 지금 정하는 것 (예: `예약 취소`)                              |
| `question`              | 진행 위치 + 왜 묻는지 한 줄 + 장면으로 쓴 질문 (규칙 1, 4, 5) |
| `options[].label`       | 짧은 답. 추천은 첫 번째에 `(추천)`                            |
| `options[].description` | 고르면 어떻게 되는지, 좋은 점·아쉬운 점 (규칙 2)              |
| 마지막 선택지           | `잘 모르겠어요` (규칙 3)                                      |

선택지는 "잘 모르겠어요"를 포함해 최대 4개다. 고를 게 셋을 넘으면 질문을 둘로 나눈다. 정답이 열려 있는 질문(예: 지금 무엇이 불편한지)은 선택지 없이 평소 메시지로 묻고, 답하기 쉽게 예시 2~3개를 붙인다.

### 예시

**나쁜 예** (이번 장비 대여 실험에서 실제로 했던 질문)

> 학생은 앱에서 어디까지 하나요?
>
> - 재고 보고 미리 예약 (추천)
> - 재고와 내 대여만 확인
> - 앱에서 대여 신청까지

**좋은 예**

> [기획서 1/5단계 · 사용자] 질문 4/약 5
> 이걸 정해야 학생 화면이 몇 개 필요한지 정할 수 있어요.
> 학생이 노트북이 필요할 때, 앱을 열어서 무엇까지 할 수 있으면 좋을까요?
>
> - **남은 수량 보고 미리 예약 (추천)** — 학생은 날짜를 골라 예약하고, 창구에서는 확인만 하고 건네요. "노트북 남았어요?" 문의가 가장 많이 줄어요. 학생 화면 2~3개, 예약 규칙(취소, 안 왔을 때)을 정해야 해요
> - **남은 수량과 내 반납일만 보기** — 빌리는 건 지금처럼 창구에서 해요. 만들 화면이 가장 적어요. 대신 창구에 왔는데 다 나가고 없을 수 있어요
> - **앱으로 지금 바로 빌리기 신청** — 예약 없이 "지금 갈게요"만 알려요. 날짜 고르는 화면은 없지만, 신청해 놓고 안 오는 경우를 따로 정해야 해요
> - **잘 모르겠어요** — Claude가 흔한 방식(미리 예약)으로 임시로 정하고, 나중에 확인할 목록에 남겨둘게요
