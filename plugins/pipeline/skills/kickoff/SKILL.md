# 길잡이

기획 담당은 스킬 이름을 외울 필요가 없다. 이 스킬이 **지금 어디까지 왔고, 다음에 무엇을 하면 되는지** 알려주고 그 스킬을 시작한다.

## 묻는 법

[`../../references/asking.md`](../../references/asking.md)를 따른다. 여기서는 질문을 최소로 한다. 상태는 파일을 읽어 Claude가 판단하고, 사용자에게는 "이걸 할까요?" 하나만 묻는다.

## 전체 지도

```
기획 (기획 레포)                                       개발 (프론트·서버 레포)
① 기획서 → ② 현장 인터뷰 → ③ 범위 → ④ 기능 명세 → ⑤ 빈틈 점검 → 화면 → API 명세 → 서버 → 연동 → 배포
   plan      interview(필요할 때)  scope    stories       red-team     design-screen ...
```

| 단계          | 스킬                      | 누가      | 어디서               | 하는 일 (한 줄)                                           | 걸리는 정도   |
| ------------- | ------------------------- | --------- | -------------------- | --------------------------------------------------------- | ------------- |
| ① 기획서      | `/pipeline:plan`          | 기획 담당 | `konkuk-icteam-plan` | 질문에 답하면 기획서가 만들어져요                         | 질문 약 20개  |
| ② 현장 인터뷰 | `/pipeline:interview`     | 기획 담당 | `konkuk-icteam-plan` | 관리자·근로학생에게 물어볼 질문지를 만들고, 답을 정리해요 | 질문지 1장    |
| ③ 범위        | `/pipeline:scope`         | 기획 담당 | `konkuk-icteam-plan` | 이번 학기에 만들 것과 미룰 것을 나눠요                    | 질문 약 6개   |
| ④ 기능 명세   | `/pipeline:stories`       | 기획 담당 | `konkuk-icteam-plan` | 기능마다 "이게 되면 완성"을 정해요                        | 기능마다 확인 |
| ⑤ 빈틈 점검   | `/pipeline:red-team`      | 기획 담당 | `konkuk-icteam-plan` | 놓친 예외 상황을 찾아 메워요                              | 빈틈마다 질문 |
| 화면          | `/pipeline:design-screen` | 기획·개발 | `konkuk-icteam-fe`   | 디자인 시스템으로 실제 화면을 만들어 봐요                 |               |
| API 명세 이후 | (준비 중)                 | 개발      | 각 레포              |                                                           |               |

개발 단계에서 Claude는 PR을 만드는 데까지만 한다. **머지는 개발자가 GitHub에서 직접 한다.**

## 진행

### 1. 프로젝트 찾기

1. 기획 레포(`konkuk-icteam-plan`, 지금 폴더 또는 옆 폴더 `../konkuk-icteam-plan`)의 `projects/`를 본다
2. 인자로 프로젝트를 받았으면 그걸 쓴다. 없으면:
   - 프로젝트가 없으면 → "새 프로젝트를 시작할게요" 하고 3번으로 (다음 스킬은 `plan`)
   - 하나면 → 그걸 쓴다
   - 여럿이면 → 목록(이름, 한 줄 소개, 단계)을 보여주고 고르게 한다. "새 프로젝트" 선택지도 둔다

### 2. 지금 단계 판단

프로젝트 폴더의 파일을 읽고 아래 순서로 처음 걸리는 것이 다음 할 일이다.

| 확인                                                                           | 다음 할 일                                                              |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| `spec.md`가 없거나, 시나리오·화면 목록·데이터 중 빈 곳이 있다                  | `plan` (이어서)                                                         |
| `열린 질문`에 현장 사람이 답할 것이 남아 있고, 그 사람의 인터뷰를 아직 안 했다 | `interview` (건너뛰어도 됨)                                             |
| `interviews/`에 '받은 답'이 빈 질문지가 있다                                   | `interview summarize`                                                   |
| `범위` 표가 비어 있다                                                          | `scope`                                                                 |
| `stories.md`가 없거나 범위의 이번 학기 기능이 다 들어 있지 않다                | `stories`                                                               |
| 진행 상황의 `빈틈 점검`이 체크되지 않았거나, 그 뒤에 기획서가 크게 바뀌었다    | `red-team`                                                              |
| 기획이 다 끝났다                                                               | `design-screen` (프론트 레포) 또는 frontmatter `stage`에 따른 다음 단계 |

진행 상황 체크리스트와 실제 파일이 다르면 파일을 믿고, 체크리스트를 고쳐 둔다.

### 3. 보여주고 시작하기

1. 전체 지도에서 지금 위치를 보여준다. 끝난 단계는 ✅, 지금 단계는 👉로 표시한다
   > ✅ ① 기획서 → 👉 ③ 범위 → ④ 기능 명세 → ⑤ 빈틈 점검 → 화면 …
   > (② 현장 인터뷰는 건너뛰었어요. 남은 열린 질문 2개는 나중에 물어봐도 돼요)
2. 다음 할 일을 한 줄로 설명하고, 얼마나 걸리는지 말하고, 시작할지 묻는다. 선택지: `시작하기 (추천)` / `다른 단계 하기` / `오늘은 여기까지`
3. 시작하기를 고르면 그 스킬을 바로 불러 이어서 진행한다 (Skill 도구로 `pipeline:<스킬>`). 다른 레포에서 해야 하는 단계면 어느 폴더를 열고 어떤 명령을 치면 되는지 알려준다
4. 오늘은 여기까지를 고르면 다음에 `/pipeline:kickoff`만 치면 이어서 할 수 있다고 알려준다

## 하지 않는 것

- 단계를 건너뛰라고 권하지 않는다. 사용자가 원하면 건너뛰되, 건너뛴 단계를 지도에 표시해 둔다
- 직접 기획서를 고치지 않는다. 고치는 일은 각 스킬이 한다 (체크리스트를 파일 상태에 맞추는 것만 예외)
