# 현장 인터뷰 (기획 2단계, 필요할 때)

기획 담당이 혼자 정할 수 없는 것(창구 운영 시간, 실제 업무 순서, 예외 상황 등)을 **답을 아는 사람에게 묻도록** 돕는다. 두 가지 모드가 있다.

| 모드        | 언제               | 결과                                                     |
| ----------- | ------------------ | -------------------------------------------------------- |
| `prep`      | 인터뷰하러 가기 전 | `projects/<프로젝트>/interviews/<날짜>-<대상>.md` 질문지 |
| `summarize` | 답을 받아 온 뒤    | 같은 파일의 '받은 답' 정리, 기획서 반영                  |

모드를 말하지 않으면, 그 프로젝트에 '받은 답'이 빈 인터뷰 파일이 있는지 보고 정한다. 있으면 "지난번에 만든 ○○ 질문지의 답을 받아 오셨나요?"라고 묻는다.

## 묻는 법

[`../../references/asking.md`](../../references/asking.md)를 따른다. 이 스킬에서는 **두 종류의 질문**이 있다는 걸 헷갈리지 않는다.

- Claude가 기획 담당에게 묻는 질문 — asking.md 규칙 그대로
- 기획 담당이 현장 사람에게 할 질문(질문지) — 아래 "좋은 인터뷰 질문" 규칙

## 준비 (`prep`)

1. 프로젝트 `spec.md`를 읽는다. 없으면 먼저 `/pipeline:plan`을 하자고 안내한다
2. 질문거리를 모은다:
   - `열린 질문`의 항목, 특히 `(임시: ...)`, `(Claude 제안, 확인 전)`으로 표시된 것
   - 기획서에 적혀 있지만 현장 사실에 기대는 것 (운영 시간, 하루 처리 건수, 지금 쓰는 엑셀 양식 등)
   - 시나리오가 실제 업무 순서와 맞는지 확인할 것
3. 모은 질문거리를 **답해줄 사람별로** 묶어 표로 보여주고, 이번에 누구를 인터뷰할지 고르게 한다
   > 이 질문들은 관리자 선생님만 답할 수 있어요: 창구 닫는 시각, 공휴일 휴무
   > 이 질문들은 근로학생이 더 잘 알아요: 하루에 몇 건 빌려주는지, 반납 때 확인하는 것
4. 고른 대상에게 할 질문지를 [`references/interview-template.md`](references/interview-template.md) 모양으로 만든다. 질문은 **5~8개**, 10분 안에 끝나게
5. 질문지를 보여주고 고칠 곳이 있는지 묻는다. 어떻게 전할지(직접 / 카톡 / 메일)도 묻는다. 카톡·메일이면 그대로 복사해 보낼 수 있게 인사말을 다듬는다
6. 파일로 저장하고, "답을 받으면 `/pipeline:interview <프로젝트> summarize`로 정리해요"라고 알려준다

### 좋은 인터뷰 질문

| 규칙                              | 이렇게 묻지 않는다                  | 이렇게 묻는다                                               |
| --------------------------------- | ----------------------------------- | ----------------------------------------------------------- |
| 지난 일을 묻는다 (상상 말고 경험) | 반납이 늦으면 어떻게 하실 건가요?   | 지난달에 반납이 늦은 학생이 있었을 때 어떻게 하셨나요?      |
| 답을 정해 두지 않는다             | 자동 취소 기능이 있으면 좋겠죠?     | 예약하고 안 오는 학생이 있으면 지금은 어떻게 처리하세요?    |
| 하나씩 묻는다                     | 운영 시간과 휴무일이 어떻게 되나요? | 창구는 몇 시에 닫나요? / (따로) 방학에도 창구를 여나요?     |
| 숫자는 예를 들어 묻는다           | 대여 기간은 어떻게 세나요?          | 월요일에 빌려서 수요일에 반납하면, 며칠 빌린 걸로 보시나요? |
| 마지막엔 열어 둔다                | (없음)                              | 이 일을 하면서 가장 번거로운 점이 있다면 무엇인가요?        |

- 기획서의 낱말(예약, 대여, 연체)을 그대로 쓰되, 질문지 처음에 한 번 뜻을 적는다
- "앱", "서버", "기능" 같은 말보다 실제 일("학생이 폰으로 미리 찜해두는 것")로 말한다

## 정리 (`summarize`)

1. 인터뷰 파일과 `spec.md`를 읽는다
2. 받은 답을 달라고 한다. 메모를 그대로 붙여 넣거나, 카톡 캡처를 올리거나, 말로 들려줘도 된다고 안내한다
3. 답을 질문별로 나눠 '받은 답' 표에 요약한다. 질문하지 않았는데 들은 것은 '새로 알게 된 것'에 적는다
4. 답마다 **기획서의 어디가 바뀌는지** 제안 목록을 만들어 보여준다
   > 1. 열린 질문 "창구 닫는 시각" → 해결: 18:00. `규칙`의 자동 취소 문장에 시각을 넣어요
   > 2. 새로 알게 된 것 "방학에는 화·목만 열어요" → `규칙`에 추가하고, 예약 달력에 영향이 있어요 ⚠️
5. 하나씩 확인받고 반영한다. 답이 기획서와 부딪히면(예: 시나리오 순서가 실제와 다름) 어느 쪽을 따를지 묻는다
6. 해결된 열린 질문은 `[x]`로 바꾸고 결과를 적는다. 답이 애매하면 '다시 물어볼 것'에 남긴다
7. 진행 상황의 `현장 인터뷰`에 체크하고, `updated`를 오늘로 바꾼다
8. 다음 단계를 알려준다: 남은 열린 질문이 없으면 `/pipeline:scope`, 다른 사람에게 물을 게 남았으면 다시 `prep`

## 하지 않는 것

- 기획 담당 대신 현장 사람에게 연락하지 않는다 (메시지·메일 전송 금지). 보낼 글만 만든다
- 받은 답을 확인 없이 기획서에 반영하지 않는다
- 받은 답에 없는 내용을 지어내지 않는다. 메모가 애매하면 '다시 물어볼 것'으로 남긴다
